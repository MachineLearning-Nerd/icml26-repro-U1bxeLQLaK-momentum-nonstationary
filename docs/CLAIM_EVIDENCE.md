# Claim-to-evidence ledger

This ledger distinguishes four things that are easy to conflate:

1. the statement extracted from the paper;
2. the clean-room producer that creates a finite or algebraic artifact;
3. the independent checker that recomputes decisive observables; and
4. the boundary of the resulting scientific verdict.

## Verification commands

Run one claim against the shipped evidence:

```bash
uv run --no-sync python repro/src/published_claim_verifier.py \
  --claim claim_3 \
  --evidence-root release/huggingface-space/evidence
```

Run the full evidence gate:

```bash
uv run --no-sync python repro/src/publication_gate.py
```

For each claim, the gate also runs `--inject-failure`. The normal run must
exit `0`; the mutation must exit nonzero. This is a check that the verifier is
not vacuous. It does not change the scientific verdict in the ledger.

## Evidence interpretation

The files named `claim_contract.json` state the quantifiers and assumptions.
`method.md` explains how the producer was run. `EVAL.md` states the route
result. `independent_checker.json` records a second computation or audit, and
`negative_control.json` records a deliberately invalid input. `limitations.md`
is part of the result, not an appendix to be ignored.

The previous three-claim `outputs/claim_verification.json` and
`outputs/PUBLICATION_GATE_PASSED.json` are preserved in Git history. The
current files at those paths are generated by the five-claim gate and are
authoritative for this repository.
